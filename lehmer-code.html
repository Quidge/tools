Lehmer Code Explorer

This page explains the same trick used by Rank Vote: take one ordering, turn it into a single integer, and recover the ordering from that integer again. The walkthroughs below stay synced with the current example.

Start Here

The goal is to number every possible ordering. If there are N items, then there are N! orderings, so the ranks run from 0 to N!-1.

Why factorials appear

Decode

Work backward from the integer: divide by the current block size to choose a block, then keep the remainder for later slots.

2. Encode: permutation -> integer

Encoding asks the same question at every slot: among the items that are still unused, how far from the left is the current pick? Those counts are the Lehmer digits.

3. Decode: integer -> permutation

Decoding does the inverse. At each slot, split the remaining rank into equal-sized factorial blocks, choose the block, then carry the remainder onward.

Names You Might See Elsewhere

People use a few different names for closely related views of the same idea. They are not different algorithms so much as different angles on the same one. This demo intentionally uses reverse-alphabetical animal names plus visible original indices so the "remaining items" list cannot accidentally look alphabetically sorted.

  • Lehmer code: the digit sequence (L0, L1, ...) where each digit counts how many unused items sit before the chosen one.
  • Factorial number system or factoradic: read those digits with place values (N-1)!, (N-2)!, ... , 1!, 0!.
  • Ranking / unranking permutations: the general name for mapping permutations to 0..N!-1 and back.
  • Cantor expansion: another name you will often see for the same ranking formula.

This is exactly the scheme the Rank Vote tool uses to turn a ranked-choice ballot into one deterministic number.
